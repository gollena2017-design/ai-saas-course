# Security and Secrets

## Що таке секрет

Секрет — це конфіденційне значення, яке дає доступ до зовнішнього сервісу, акаунта або бази даних.

Секрети не можна публікувати у відкритому вигляді, додавати до Git-репозиторію або передавати у повідомленнях.

До секретів у цьому проєкті належать токени доступу та дані для підключення до бази даних.

## Які секрети є у проєкті

У проєкті використовуються такі секрети:

* `BOT_TOKEN` — токен Telegram-бота, який використовується для доступу до Telegram Bot API;
* `DATABASE_URL` — рядок підключення до PostgreSQL у Neon.

`DATABASE_URL` може містити:

* ім'я користувача бази даних;
* пароль;
* адресу сервера;
* порт;
* назву бази даних;
* параметри підключення.

Тому `DATABASE_URL` потрібно зберігати так само безпечно, як пароль.

## Де зберігаються секрети

Реальні секрети зберігаються тільки у локальному файлі `.env`.

Приклад:

```env
BOT_TOKEN=real_telegram_bot_token
DATABASE_URL=real_database_connection_string
```

Файл `.env` не повинен потрапляти до Git.

У `.gitignore` повинні бути правила:

```gitignore
.env
.env.*
!.env.example
```

Ці правила означають:

* `.env` не комітиться;
* інші локальні `.env.*` файли не комітяться;
* `.env.example` дозволено додавати до Git.

## Різниця між `.env` і `.env.example`

### `.env`

Файл `.env` містить реальні значення секретів.

Наприклад:

```env
BOT_TOKEN=123456789:real_token
DATABASE_URL=postgresql://real_user:real_password@host/database
```

Цей файл використовується тільки локально або у захищеному середовищі запуску застосунку.

`.env` не можна:

* комітити у Git;
* публікувати у GitHub;
* додавати до README;
* надсилати у Telegram або інші месенджери;
* показувати на скріншотах;
* виводити у logs.

### `.env.example`

Файл `.env.example` містить тільки назви змінних та безпечні приклади-заглушки.

Наприклад:

```env
BOT_TOKEN=your_bot_token_here
DATABASE_URL=your_database_url_here
```

Цей файл можна і потрібно комітити.

Він допомагає іншим розробникам зрозуміти, які environment variables потрібно створити для запуску проєкту.

## Як застосунок отримує секрети

Python-код не повинен містити реальні токени або паролі.

Замість цього значення завантажуються зі змінних середовища.

Наприклад:

```python
import os

from dotenv import load_dotenv

load_dotenv()

BOT_TOKEN = os.getenv("BOT_TOKEN")
DATABASE_URL = os.getenv("DATABASE_URL")
```

Таким чином секрети відокремлені від вихідного коду.

## Що робити при витоку секрету

Якщо секрет випадково потрапив у GitHub, Pull Request, screenshot, log, повідомлення або інше публічне місце, потрібно вважати його скомпрометованим.

Недостатньо просто видалити секрет з файла.

Потрібно:

1. Негайно відкликати або змінити скомпрометований секрет.
2. Для Telegram-бота — перевипустити `BOT_TOKEN`.
3. Для Neon — змінити пароль або створити нові облікові дані для бази.
4. Оновити нове значення у локальному `.env`.
5. Переконатися, що `.env` знаходиться у `.gitignore`.
6. Перевірити `git status` і `git diff`.
7. За потреби видалити секрет з історії Git.
8. Перевірити, що новий секрет не виводиться у logs.

## Перевірка перед commit

Перед кожним commit потрібно виконати:

```bash
git status
```

Також корисно перевірити зміни:

```bash
git diff
```

Перед push потрібно переконатися, що у змінених файлах немає:

* реального `BOT_TOKEN`;
* реального `DATABASE_URL`;
* пароля бази даних;
* інших конфіденційних значень.

Головне правило проєкту:

```text
.env не комітимо.
.env.example комітимо.
.gitignore комітимо.
Секрети не зберігаємо у коді.
```
